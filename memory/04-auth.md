# 04 — Authentication (Better Auth)

## Status: MIGRATED

On 2026-08-19 Supabase Auth was **fully replaced** by Better Auth 1.7.1. Supabase is now used **only** as the PostgreSQL host (via Prisma). Reason: single auth authority, no vendor lock on identity, full control of the session model, and the Better Auth Dash dashboard.

## Architecture

- `src/lib/auth/better-auth.ts` — the Better Auth instance:
  - `prismaAdapter(prisma, { provider: "postgresql" })`
  - `emailAndPassword: { enabled: true }` — core option (NOT a plugin in 1.7.x)
  - `dash({ apiKey: process.env.BETTER_AUTH_API_KEY })` from `@better-auth/infra`
  - `baseURL`: production → `BETTER_AUTH_URL` (https://keebforge.in); dev → `http://localhost:3000`
  - `secret`: `BETTER_AUTH_SECRET`
- `src/app/api/auth/[...all]/route.ts` — `toNextJsHandler(auth)` from `better-auth/next-js`; serves `/api/auth/*`.
- `src/lib/auth.ts` — app-facing helpers:
  - `getCurrentAuth()` → `{ user, profile }` or `{ user: null, profile: null }`. **Auto-creates the `Profile` on first access** with role `CUSTOMER`, and links the seeded ADMIN profile by email (claim-by-email): if the signed-in user's email matches an existing admin profile, the profile is linked to the user and role `ADMIN`. NEVER auto-provisions a *new* ADMIN.
  - `requireUser()` / `requireAdmin()` — server-side guards (redirect to `/login` / `/`).
  - `isAdminRole(role)` — ADMIN or STAFF.

## Database

Better Auth models are generated by the CLI (`npx @better-auth/cli generate`) — `User`, `Session`, `Account`, `Verification` (lowercase table names). The KeebForge business identity lives in `Profile`, linked to `User` via `Profile.userId` (nullable + unique — the seeded admin profile only gets its `userId` once the owner signs in, via claim-by-email).

### Known CLI bug (fixed)

The CLI's generated schema was **missing the `Account.issuer` column** that the runtime actually requires (visible via `getAuthTables`). It was added manually to `schema.prisma` plus migration `20260819181000_better_auth_account_issuer`. If you ever re-generate auth schema, re-check that `Account` includes `issuer String?`.

## Optional packages installed (why)

`@better-auth/sso` and `@better-auth/scim` are installed because `@better-auth/infra` contains dynamic `import("@better-auth/sso")` / `import("@better-auth/scim")` calls, and Next.js Turbopack **statically resolves dynamic imports** and fails the build if the module is missing. They are never invoked (no SSO/SCIM configured) but must stay installed, or remove them together with the `dash()` plugin. `@better-auth/sso` is also listed in `next.config.ts` `serverExternalPackages`.

## Verified behaviors (2026-08-19, local dev)

- `GET /api/auth/get-session` → `null` when signed out, session object when signed in.
- `POST /api/auth/sign-up/email` → 200, creates `user` + `account` (provider `credential`, password hash) rows.
- `POST /api/auth/sign-in/email` → 200 with session; wrong password → 401.
- `POST /api/auth/sign-out` → session null afterwards.
- CSRF: state-changing POSTs require an `Origin` header matching the host. **curl needs `-H "Origin: http://localhost:3000"`** or you get 403 (browsers always send it). `sign-out` also requires a `{}` JSON body.

## The old Supabase auth (removed)

- Files deleted: `src/lib/supabase/{client,server,middleware}.ts`.
- Dependencies removed: `@supabase/ssr`, `@supabase/supabase-js`.
- `src/proxy.ts` previously refreshed Supabase sessions in middleware; it now only performs case-variant redirects (Better Auth manages its own cookies).

## Security posture

- `BETTER_AUTH_SECRET` and `BETTER_AUTH_API_KEY` are server-only env vars — never in client code, HTML, or logs.
- Roles: `CUSTOMER` (default), `STAFF`, `ADMIN` — assigned explicitly, never auto-promoted.
- All authorization checks happen server-side.
